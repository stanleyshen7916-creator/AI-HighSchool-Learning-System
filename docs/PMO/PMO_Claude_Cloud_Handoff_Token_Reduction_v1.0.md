# PMO｜雲端 Claude 交接：降低 token 用量的作業調整 v1.0

- 建立日期：2026-11-13
- 建立者：桌機帳號 Claude（依 Stanley 指示）
- 執行者：雲端帳號 Claude
- 相關文件：`docs/PMO/PMO_Claude_Dual_Account_Workflow_v1.0.md`
- 本 repo 為公開 repo：本文件與後續產出都不得寫入金鑰、token、內部位址、連接埠或安全弱點細節。

## 1. 背景

2026-11-11～11-13 桌機帳號在單一 session 內連續完成帳號分工文件、Notion 整併、交辦盤點、環境盤點、Dashboard MVP、欄位擴充與線上補驗，token 用量偏高。原因如下：

| # | 原因 | 說明 |
| --- | --- | --- |
| 1 | 單一 session 任務過多 | 每一輪都重送全部歷史，越後面越貴 |
| 2 | session 跨多天 | 快取過期後以全價重讀整段歷史 |
| 3 | 讀取過大的 Notion 頁面 | 派工內容只在頁首，卻要讀進數萬字的歷史快照 |
| 4 | 回報過長且多輪 | 同一任務寫了 2～3 輪長報告 |
| 5 | 服務未先啟動 | 造成盤點與驗證多次來回 |
| 6 | 治理流程固定成本高 | 每個任務都做備份、hash、自評表、證據索引 |
| 7 | 掛載的連接器過多 | 用不到的工具清單每一輪都計入 |

## 2. 兩個帳號共同遵守的作業規則

1. 一個任務一個 session，完成即結束；不在同一個 session 接續不相關的任務。
2. 開工前確認前置條件已就緒（需要的服務已啟動、需要的分支已 push）。前置未就緒就先回報，不反覆重試。
3. 讀 Notion 時只查詢需要的資料庫列或頁面區段，不整頁讀取含歷史快照的大頁面。
4. 回報使用第 5 節的短格式，一個任務只寫一份；後續更新改寫同一份的對應欄位，不追加新的一輪長文。
5. 證據留在檔案（repo 或本機資料夾），回報只附路徑或連結。
6. 只啟用該任務需要的連接器。
7. 唯讀盤點與文件整理使用較小的模型；架構設計與複雜實作才使用高階模型。

## 3. 雲端 Claude 的任務

依序執行。每個任務各開一個 session、各開一個 PR 或各交一份產出。

### C-1｜把作業規則併入分工文件（可立即執行）

- 範圍：只改 `docs/PMO/PMO_Claude_Dual_Account_Workflow_v1.0.md`。
- 內容：新增一節「省 token 作業規則」，寫入本文件第 2 節的 7 條規則與第 5 節的短回報格式；在「雲端帳號」「桌機帳號」兩節各補一句對應的分工說明（見第 4 節）。
- 完成標準：`npm run verify` 與 `npm test` 通過；開一個 PR；PR 說明列出變更的節次。
- 限制：不改其他檔案；不合併 PR。

### C-2｜草擬 Notion 派工資料庫與短回報範本（需前置 P-2）

- 目的：讓派工從「頁面中的自由文字」改為「資料庫列」，之後各 AI 只需查詢未完成的列。
- 產出：一份提案頁，內容為 (1) 派工資料庫的欄位設計：Task ID、名稱、狀態、負責角色、範圍、驗收條件、限制、成果連結、建立時間；(2) 狀態選項，沿用現行流程的 READY／IN PROGRESS／SELF-QA／SUBMITTED／GPT REVIEW／DONE／REWORK／BLOCKED；(3) 第 5 節短回報格式的範本；(4) 既有大頁面的歷史快照搬到子頁的建議清單。
- 完成標準：提案頁建立在 Notion「AI 協作與交接」區，並在「AI 訊息匣」寄一則給 GPT（類型＝交接）附上連結。
- 限制：只新增提案頁與一則訊息；不修改 Dashboard 頁、不搬動或刪除任何既有頁面、不建立正式資料庫。是否採用由 GPT 與 Stanley 決定。

### C-3｜AI Agent 平台程式類工作（需前置 P-1）

- 範圍：Stanley 另行建立的私有 repo（Bridge／Dashboard 專案）。本公開 repo 不放該專案的任何程式或設定。
- 工作項目：
  1. 新增工作包欄位的操作腳本，風格比照既有的提交審查腳本：token 只從當前 PowerShell session 的環境變數讀取，不讀 `.env`；可更新 `test_status`、`owner_acceptance`、`gate_status` 等欄位，並可傳入空字串清除。
  2. 為上述腳本與既有離線測試補上必要測試。
  3. 提出「Bridge 開機自動啟動」的做法比較（只寫提案，不實作）。
- 完成標準：離線測試全數通過並附測試數與 Exit Code；開一個 PR；PR 說明註明「線上驗證待桌機帳號執行」。
- 限制：不執行任何需要線上服務的測試；不修改 n8n workflow；不提交 `.env`、workflow 匯出檔或任何含 token 的檔案；不合併 PR。

## 4. 分工界線

| 工作 | 負責帳號 | 原因 |
| --- | --- | --- |
| 程式修改、離線測試、文件、PR | 雲端 | 只靠 repo 即可完成 |
| Notion 提案與短回報 | 雲端 | 前提是雲端帳號已接上 Notion |
| 本機環境盤點、服務啟停後的檢查 | 桌機 | 需要本機的容器與服務 |
| 線上驗證、瀏覽器實測 | 桌機 | 入口只在本機 |
| 拉取 PR 分支後的整合確認 | 桌機 | 需要與線上服務一起驗 |
| 合併 PR、Owner Acceptance | Stanley | 最終決定權 |

桌機帳號在雲端 PR 開出後只做一件事：拉取分支、啟動服務、驗證、回報結果。

## 5. 短回報格式

每個任務只寫一份，總長以一個螢幕為限。

| 欄位 | 內容 |
| --- | --- |
| Task ID／名稱 | 對應交辦項目 |
| 狀態 | SELF-QA／SUBMITTED／BLOCKED |
| 成果連結 | PR 連結或可開啟的入口 |
| 變更摘要 | 三行以內，加檔案清單 |
| 測試 | 命令、測試數、通過數、Exit Code |
| 自評 | 分數與扣分原因，各一行 |
| 限制 | 未完成與未驗證的項目 |
| 證據位置 | 路徑或連結，不貼內容 |
